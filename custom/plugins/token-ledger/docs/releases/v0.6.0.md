# TokenLedger v0.6.0

Released 2026-09-23. This release adapts TokenLedger to Paseo 0.9.1, restores tracking after subscription failures, and adds native settings for summaries, reference prices, and refresh frequency.

## Compatibility and upgrade

Both the Paseo daemon and app must be **0.9.1–0.9.x** (`>=0.9.1 <0.10.0`). Use TokenLedger `v0.5.1` with Paseo 0.8, or `v0.3.1` with Paseo 0.7.

For a new installation:

```bash
paseo plugin add stv1024/token-ledger --ref v0.6.0
```

For an existing GitHub installation, update Paseo first, then run:

```bash
paseo plugin update token-ledger --check
paseo plugin update token-ledger --ref v0.6.0
paseo plugin ls
```

TokenLedger should be `running`. Local development installations use `paseo plugin reload token-ledger`. Reopen the desktop app if an existing window still holds the previous UI bundle.

Existing ledger records, checkpoints, and `pricing.json` overrides remain compatible; no data migration or deletion is required. Install/update selectors do not pin future updates: without `--ref`, Git updates follow the remote's default branch.

## Changes

- **Paseo 0.9.1 subscriptions:** use host-assigned subscription handles, reconcile complete paginated catalogs after reconnect, retain live updates received during pagination, and await handle release during cleanup.
- **Recovery and accounting:** retry timeline subscription failures with bounded delays. Persist delivery gaps through reloads, display affected turns with `gap`, and use `unknown` when the terminal outcome was missed. Keep cumulative costs spanning an unobserved interval as raw data instead of assigning the entire amount to one turn.
- **Native settings:** open **Settings → Plugins → token-ledger → TokenLedger** to control Timeline summaries, OpenRouter reference prices, built-in fallback prices, and refresh frequency. The switches default to on; normal polling uses 3 seconds active / 30 seconds idle, and relaxed polling uses 10 / 60 seconds. Preferences apply to the selected host without reloading the plugin.
- **Live cost estimates:** show the current turn's estimated cost in the panel and include it in the composer pill's running total. Estimates retain the `≈` mark.
- **Reference prices:** refresh verified standard Claude rates, including Opus 5.5, against Anthropic's pricing table dated 2026-09-23. Match explicit model versions so unknown versions and Fast/Batch suffixes do not inherit an unverified built-in price. Reported costs and custom overrides keep priority.
- **Optional cache-write accounting:** carry supplied write counts through aggregation, persistence, RPCs, and UI, with an independent `cacheWrite` rate and OpenRouter write-price ingestion. Separate known cache counts from inclusive input, use complete prompt sizes for pricing tiers, and avoid normalizing live input twice.

## Known data and validation limits

Paseo 0.9.1 still omits cache-write counts and provider-internal descendant usage from its public plugin usage API. Optional cache-write support does not recover those missing streams or reconstruct historical counts. Codex observations remain `partial` because identical requests cannot always be distinguished from replayed snapshots. Recovery marks missing data and does not backfill historical Timeline summaries.

Validation on Node 24 and Paseo 0.9.1 includes TypeScript checking, all 65 automated tests, plugin reload/startup, real Claude and Codex turns, preservation of Claude session-cost deltas across reload, catalog pagination beyond 200 entries, unchanged-record RPC responses, and native-settings read/write/validation/conflict behavior. Test agents were archived and settings were restored after verification.

Desktop and mobile visual checks were not completed because native UI automation was unavailable. These checks do not establish visual behavior of the settings page or Timeline renderer on either platform.
